💾 Variable Store & Chaining

Store response values and use them in subsequent requests for complex workflows:

Global Variables

Persist across all test cases in a suite:

{
  "testData": [
    {
      "name": "Create User",
      "method": "POST",
      "endpoint": "/users",
      "body": {
        "name": "John Doe",
        "email": "john@example.com"
      },
      "store": {
        "userId": "$.id",
        "userEmail": "$.email"
      }
    },
    {
      "name": "Get User",
      "method": "GET",
      "endpoint": "/users/{{userId}}",
      "assertions": [
        {
          "type": "equals",
          "jsonPath": "$.email",
          "expected": "{{userEmail}}"
        }
      ]
    }
  ]
}

Local Variables

Cleared after each test case:

{
  "storeLocal": {
    "tempToken": "$.token",
    "sessionId": "$.session.id"
  }
}

Cookie Storage

Store cookies from responses:

{
  "storeCookie": {
    "authCookie": "auth_token"
  }
}

Variable Injection

Use stored variables anywhere in your tests:

{
  "endpoint": "/users/{{userId}}/orders",
  "headers": {
    "Authorization": "Bearer {{authToken}}"
  },
  "body": {
    "userId": "{{userId}}",
    "timestamp": "{{currentTime}}"
  }
}

🔧 PreProcess Functions

Generate dynamic data before test execution:

Faker Functions

Generate realistic fake data:

faker.email

{ "var": "email", "function": "faker.email" }

Output: john.doe@example.com

faker.uuid

{ "var": "id", "function": "faker.uuid" }

Output: 550e8400-e29b-41d4...

faker.name

{ "var": "name", "function": "faker.name" }

Output: John Doe

faker.phone

{ "var": "phone", "function": "faker.phone" }

Output: +1-555-123-4567

Date/Time Functions

{
  "preProcess": [
    {
      "var": "timestamp",
      "function": "date.now"
    }
  ]
}

Encryption Functions

{
  "preProcess": [
    {
      "var": "encryptedPassword",
      "function": "encrypt",
      "args": ["MySecretPassword123"]
    }
  ]
}

Database Queries

{
  "preProcess": [
    {
      "function": "dbQuery",
      "args": ["SELECT id, name FROM users WHERE role = 'admin' LIMIT 1"],
      "db": "userDb",
      "mapTo": {
        "adminId": "id",
        "adminName": "name"
      }
    }
  ]
}

Complete Example

{
  "name": "Create User with Dynamic Data",
  "method": "POST",
  "endpoint": "/users",
  "preProcess": [
    { "var": "randomName", "function": "faker.name" },
    { "var": "randomEmail", "function": "faker.email" },
    { "var": "randomPhone", "function": "faker.phone" },
    { "var": "timestamp", "function": "date.now" }
  ],
  "body": {
    "name": "{{randomName}}",
    "email": "{{randomEmail}}",
    "phone": "{{randomPhone}}",
    "createdAt": "{{timestamp}}"
  }
}

✅ Assertions

TestFlow Pro provides 20+ assertion types for comprehensive validation:

Basic Assertions

Type Description Example
equals Strict equality { "type": "equals", "jsonPath": "$.id", "expected": 1 }
notEquals Inverse equality { "type": "notEquals", "jsonPath": "$.status", "expected": "deleted" }
contains Value contains expected { "type": "contains", "jsonPath": "$.name", "expected": "John" }
exists Path exists in response { "type": "exists", "jsonPath": "$.id" }
statusCode HTTP status code { "type": "statusCode", "expected": 200 }

String Assertions

Type Description
startsWith String starts with value
endsWith String ends with value
regex Matches regex pattern
length String/array length

Numeric Assertions

Type Description
greaterThan Value > expected
lessThan Value < expected
greaterThanOrEqual Value >= expected
lessThanOrEqual Value <= expected

Array Assertions

Type Description
in Value is in array
notIn Value not in array
includesAll Array includes all values
size Array/object size
arrayObjectMatch Find object in array

Advanced Assertions

{
  "assertions": [
    {
      "type": "arrayObjectMatch",
      "jsonPath": "$.users",
      "searchKey": "email",
      "searchValue": "john@example.com",
      "assertions": [
        { "type": "equals", "jsonPath": "$.role", "expected": "admin" },
        { "type": "exists", "jsonPath": "$.id" }
      ]
    }
  ]
}

🎭 UI Testing with Playwright

Powerful browser automation with multiple locator strategies:

Locator Strategies

CSS Selector

{ "strategy": "css", "value": "#username" }

XPath

{ "strategy": "xpath", "value": "//input[@id='username']" }

Text

{ "strategy": "text", "value": "Login" }

Placeholder

{ "strategy": "placeholder", "value": "Enter username" }

UI Test Example

{
  "testCases": [
    {
      "name": "Login Test",
      "type": "UI",
      "testSteps": [
        {
          "keyword": "goto",
          "value": "https://example.com/login"
        },
        {
          "keyword": "type",
          "locator": { "strategy": "css", "value": "#username" },
          "value": "john@example.com"
        },
        {
          "keyword": "type",
          "locator": { "strategy": "css", "value": "#password" },
          "value": "password123"
        },
        {
          "keyword": "click",
          "locator": { "strategy": "text", "value": "Login" }
        },
        {
          "keyword": "assertVisible",
          "locator": { "strategy": "text", "value": "Welcome" }
        }
      ]
    }
  ]
}

Query databases directly in your tests:

Supported Databases

IBM DB2 database support

Configuration

# .env file
DB_USERDB_TYPE=mysql
DB_USERDB_HOST=localhost
DB_USERDB_PORT=3306
DB_USERDB_USER=root
DB_USERDB_PASSWORD=secret
DB_USERDB_NAME=testflow

Usage in Tests

{
  "preProcess": [
    {
      "function": "dbQuery",

      "db": "userDb",

        "userId": "id",
        "userName": "name",
        "userEmail": "email"

    }
  ],
  "endpoint": "/users/{{userId}}",
  "assertions": [
    {
      "type": "equals",
      "jsonPath": "$.name",
      "expected": "{{userName}}"
    }
  ]
}
